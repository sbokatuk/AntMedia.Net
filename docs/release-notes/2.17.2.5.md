## What's changed

Peer-to-peer calls, and the Apple fixes that shook out of testing a real call between a Mac and
an iPhone. The native layer is unchanged — same SDK pins as
[2.17.2.4](https://github.com/sbokatuk/AntMedia.Net/blob/main/docs/release-notes/2.17.2.4.md).

### Peer-to-peer calls

**`IAntMediaClient.JoinAsync(streamId)`** joins a two-party call: both devices join the same id,
the server relays only signalling, and media flows directly between them. The sample gained a
**Join (P2P)** button next to Publish and Play. Worth knowing before you wire it up:

- **The server must be Enterprise edition.** The free community server supports WebRTC
  *publishing only*: its websocket handler answers every `play` with `no_stream_exist` — even
  for a live stream — and ignores `join` without answering at all, so against community,
  `JoinAsync` can only time out. (Its command dispatch handles exactly publish,
  takeConfiguration, takeCandidate, stop and ping.) To check a publish against a community
  server, watch the server's HLS output instead.
- **When the returned task completes differs per platform**, documented on the method: Android
  confirms the join itself, while the Apple SDK surfaces nothing until the other peer connects —
  so the first participant's task waits for the second. Give the waiting side a generous
  `AntMediaOptions.Timeout` (the sample uses 90 seconds).
- On Android a call attaches both video renderers — local preview and remote — where publish and
  play each use one.

### Apple fixes from live testing

- **A second `PublishAsync`/`PlayAsync` now ends the previous session first**, as the interface
  always promised and Android always did. Without it, a repeat publish collided with the
  client's *own* live stream server-side (`streamIdInUse`), tore both sessions down, froze the
  preview, and left a zombie broadcast on the server that answered every play with
  `no_stream_exist`.
- **Video containers clip the SDK's renderer.** It scales to fill and UIKit does not clip
  subviews, so a frame whose aspect or rotation mismatched the container painted far outside
  it — over the rest of the page.
- **Mac Catalyst renders the local preview upright.** The capturer stamps frames with the device
  orientation; a Mac has none, the SDK assumes portrait, and the webcam appeared sideways. The
  local renderer's rotation is pinned; remote video is untouched, since it carries the sender's
  real rotation. (The *outgoing* Mac stream still carries the portrait stamp — a remote peer
  shows it rotated; fixing that needs a custom capturer upstream.)

### Sample

Join button and mode-aware permissions; a press during a running session restarts it cleanly
and says so in the log; `NSLocalNetworkUsageDescription` in the iOS manifest, since streaming to
an Ant Media Server on your own LAN triggers iOS 14+'s Local Network prompt; and the readme now
documents the community-edition limitations up front.

## Upgrading

No behaviour changes for package consumers. One source-level note: `IAntMediaClient` gained
`JoinAsync`, so a custom implementation of the interface — a test double, say — needs the new
member.

Everything in the
[2.17.2.4 notes](https://github.com/sbokatuk/AntMedia.Net/blob/main/docs/release-notes/2.17.2.4.md)
still applies, including its three deliberate behaviour changes if you are coming from 2.17.2.3.
