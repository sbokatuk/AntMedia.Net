## What's changed

Windows no longer breaks the build. The native layer is unchanged — same SDK pins as
[2.17.2.4](https://github.com/sbokatuk/AntMedia.Net/blob/main/docs/release-notes/2.17.2.4.md).

### A MAUI app that targets Windows now restores

`AntMedia.Net` and `AntMedia.Net.Maui` gained a plain `net8.0`/`net9.0`/`net10.0` assembly, which
is what a Windows target framework resolves to.

Before this, adding the package to an app that mentioned Windows anywhere failed restore outright:

```
error NU1202: Package AntMedia.Net.Maui is not compatible with net10.0-windows10.0.19041.0
```

and NuGet fails the *whole* project, not the Windows leg alone. `dotnet new maui` adds
`net*-windows` to `TargetFrameworks` whenever the developer is on Windows, so this hit everyone
building a MAUI **Android** app from a Windows machine — work that needs no Mac and no Apple SDK.
The documented workaround was a conditional `PackageReference`; it is no longer needed, and can be
dropped.

Nothing streams there — Ant Media publishes WebRTC SDKs for Android and iOS only, so there is no
Windows library to bind. What the assembly does is let the code compile and the app run:

- `UseAntMedia()`, `AntMediaOptions.CreateClient()`, `SetLocalView`/`SetRemoteView` and every
  member of `IAntMediaClient` are present, so shared code and XAML need no `#if`.
- `AntMediaVideoView` is an empty `ContentView`. A page containing one lays out and appears
  instead of throwing "Handler not found".
- `PublishAsync`, `PlayAsync` and `JoinAsync` throw `PlatformNotSupportedException`, naming the
  supported platforms. Guard those three calls with `#if ANDROID || IOS || MACCATALYST`.
- The plain dependency groups pull in no binding, so a Windows consumer never downloads an
  Android `.aar` or an Apple `xcframework`.

The same asset covers a plain `net9.0` project — a unit-test project referencing the client, for
instance, which used to fail restore for the same reason.

### Upstream watching

The `upstream-drift` workflow now runs daily rather than weekly and files one issue per platform,
so the title says where the change is. Android is watched on two axes: a newer tag, and a newer
GitHub release. A standing drift stays quiet — each report carries a fingerprint, so a repeat
posts nothing, a change comments, and drift going away closes the issue. It also no longer reports
iOS drift on every run: `ls-remote <url> HEAD` matches on the tail of a ref name, and that
repository has a stray `refs/remotes/origin/HEAD`, so the check was reading two commits as one.

## Upgrading

No behaviour changes on Android, iOS or Mac Catalyst — those assets are byte-for-byte what they
were. If your app carries the conditional `PackageReference` from the old readme, delete the
condition.

Everything in the
[2.17.2.5 notes](https://github.com/sbokatuk/AntMedia.Net/blob/main/docs/release-notes/2.17.2.5.md)
still applies.
